<objective>
Implement the hand-written FIND-before-write cache (`find_cache.py`) that makes the RED
`test_find_cache.py` tests from Plan 01 GREEN. `write()` persists an agent-handed `*_FIND`
result to `data/ads_<entity>_find_<date>.json`; `lookup()` returns the cached entity on a HIT

stale ID. No socket; the FIND JSON is handed in by the agent (the seam).

`thresholds.read → None → refuse` missing→refuse grammar exactly.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent-handed FIND JSON → cache file | A changed/partial FIND shape could be cached and later read as a valid entity |
| cache file (a stale snapshot) → write build | A days-old cached ID may name a paused/archived/renamed entity |
| dict-walk on a missing ID → write payload | A miss returning a falsy/empty value could let a fabricated ID through |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07 | Tampering | find_cache.lookup → write build | mitigate | A cache miss returns `Refusal("stale/missing entity ID","find_cache_miss")`, never a fabricated ID; the write builder stops on the Refusal (FIND-before-write, WRITE-02; test_uncached_id_refuses). |
| T-06-08 | Tampering | find_cache.write FIND-item shape | mitigate | pydantic `_FindItem` validate-or-raise on each item; a renamed/missing id field raises ValueError (drift surfaced), never silently cached (Task 1). |
| T-06-09 | Tampering | stale cache file | mitigate | Dated cache filenames + lookup prefers the NEWEST file (Pitfall 3); the operator staleness window is a documented Phase-8 dial, not a silent hard-coded default (RESEARCH A2). |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan (RESEARCH §Package Legitimacy Audit: zero new deps). No legitimacy checkpoint required. |
